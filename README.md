## 📌 Problem Statement

Students juggling multiple subjects close to an exam rarely know how to split their limited time across topics. Most just study whatever feels comfortable first — meaning the subjects they're already good at get over-studied while the ones they're weak on get rushed or skipped entirely.

The result is uneven prep and, often, panic-cramming the night before an exam — not because students don't want to plan, but because building a *good* plan by hand (one that actually accounts for confidence level, spacing, and time left) is tedious and easy to get wrong under pressure.

## 💡 Solution Description

StudySprint asks a student for three things — their exam date, hours available per day, and every topic left to cover rated **weak / medium / strong** — and turns that into a day-by-day study schedule generated by Google's Gemini API.

The AI prompt is built to:
- give **weak** topics more sessions, repeated more than once
- give **strong** topics a single light review instead of repeated time
- spread topics across days for spaced repetition, instead of clumping one subject into one block
- keep the final day (or two) before the exam **recap-only** — no new material right before the test

The plan renders as a **sprint track** — a checkpoint-style timeline the student can check off session by session, with progress saved locally in the browser so it survives a refresh.

## ✨ Features

- 🎯 Confidence-based prioritization (weak topics get more time automatically)
- 🗓️ Full day-by-day schedule generated in one request, from today to exam day
- ✅ Checkable sessions with a live progress bar
- 💾 Progress saved locally — no login or account needed
- 🖨️ Export / print the finished plan
- 🎨 Custom "sprint track" visual design, built distinct from generic form UIs

## 🛠️ Tech Stack

| Layer | Choice |
|---|---|
| Frontend | Single-page HTML/CSS/JS — no framework, no build step |
| Backend | Vercel serverless function (`/api/generate-plan.js`) |
| AI Model | Google Gemini (`gemini-3.5-flash-lite`) |
| Storage | Browser `localStorage` — no database needed |
| Hosting | Vercel (free tier) |

> The repo also keeps an earlier Express + Node backend under `backend/` and `frontend/`, used for local development before the project was adapted into a Vercel serverless function for deployment. The version actually live in production is the root `index.html` + `api/generate-plan.js`.

## 🚀 Running It Locally

### Option A — Vercel dev (matches production)

```bash
npm install -g vercel
vercel dev
```

Set `GEMINI_API_KEY` in a local `.env` file at the project root, or pull it with `vercel env pull` if the project is already linked.

### Option B — Express version

```bash
cd backend
npm install
cp .env.example .env
# paste your Gemini API key into .env
npm start
```

Then open `frontend/index.html` directly in a browser — it talks to `http://localhost:5050/api/generate-plan`.

## ☁️ Deploying Your Own Copy

1. Push the repo to your own GitHub account.
2. Go to [vercel.com](https://vercel.com) → **Add New Project** → import the repo.
3. Leave build settings as default — Vercel auto-detects `api/` as serverless functions and serves `index.html` as the static site.
4. Under **Environment Variables**, add `GEMINI_API_KEY` with a key from [Google AI Studio](https://aistudio.google.com/app/apikey).
5. Click **Deploy**.

No credit card required for Vercel's free tier.

## 👩‍⚖️ Notes for Judges

- Get a free Gemini API key at https://aistudio.google.com/app/apikey to test with your own credentials — the live deployment already has one configured.
- No student data is stored anywhere except the browser's `localStorage` for checkbox progress. Topic names and confidence levels are sent to Gemini solely to generate the plan and are not saved server-side.
- Gemini's available model lineup changes frequently — if `gemini-3.5-flash-lite` is ever deprecated, swap the `GEMINI_MODEL` constant in `api/generate-plan.js` for whatever Google's current lightweight model is.
